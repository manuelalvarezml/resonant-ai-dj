# S3 storage decision

Reviewed 2026-10-02. Choose **S3 Standard in us-east-2**, using general-purpose buckets. Audio is pre-existing MP3; streaming means normal HTTPS GET/HEAD and byte ranges, with no transcoding or MediaConvert service. [S073–S076](SOURCES.md).

## Class comparison for this library

Ohio prices were read from the public AWS regional price list; not inferred from another region. MP3 inventory = 1,910,985,140 bytes = 1.7797436006 GiB. AWS storage billing uses binary GB units; displayed decimal GB elsewhere is only a size label.

| Class | Behavior / relevant charge | Fit |
|---|---|---|
| **Standard** | $0.023 per GB-month, no per-GB retrieval fee; designed 99.99% availability | **Choose.** About $0.0409/month for current MP3 bytes, before requests/credits |
| Standard-IA | $0.0125 per GB-month plus $0.01 per GB retrieved; 30-day minimum and 128 KB minimum billable object size | About $0.0222 storage. Maximum initial saving about $0.0187/month; roughly 1.87 GB of origin retrieval already consumes it, before higher requests/minimums |
| Intelligent-Tiering | Frequent tier matches Standard; monitoring $0.0025/1,000 eligible objects/month; small objects under 128 KB stay frequent without monitoring | Valid later for a larger unpredictable library; 187 monitored tracks cost only $0.0004675/month, so the fee itself is not the objection. Savings are tiny now; avoid unnecessary automatic tier policy and disable asynchronous archive tiers if adopted |
| One Zone-IA | Single AZ with retrieval/minimum-duration considerations | Reject for primary playback; avoid weakening resilience to save pennies |
| Glacier Instant Retrieval | Immediate access, but retrieval fees and 90-day minimum | Technically streamable; not sensible for an actively shared small library |
| Glacier Flexible / Deep Archive | Restore workflow and delayed retrieval | Reject for active media/catalog/models; cannot satisfy direct playback |
| Express One Zone | Single-AZ low-latency analytics-oriented storage | Unneeded performance/cost model for MP3 delivery through a CDN |

Storage-class constraints: [AWS class guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html), [S3 pricing](https://aws.amazon.com/s3/pricing/). Standard stores across at least three AZs; durability is not the same as uptime or immunity from an authorized deletion. [S3 FAQ](https://aws.amazon.com/s3/faqs/).

The IA break-even calculation uses **origin retrieval**, not every byte CloudFront serves. A cache hit avoids origin retrieval. Even a perfect cache cannot make the current maximum two-cent saving material. No life-cycle transition to IA/archive for any active-release object.

## Three buckets, clear permissions

Buckets have no standing per-bucket rental charge; separating purposes simplifies IAM and lifecycle. Actual unique names are generated by infrastructure code, never guessed from the account suffix.

| Bucket | Contents | Access / versioning |
|---|---|---|
| `site-media` | `login/`, `app/releases/<id>/`, `library/releases/<id>/page-N.json`, `library/current.json`, `media/<sha256>.mp3`, one `media/mix-<hash>.m4a` | CloudFront OAC reads approved prefixes. Versioning on. No browser writes |
| `release-private` | Original `release.json`, raw feature evidence, frozen planner/parity, model manifest/assets, deployment inventory | Deployment role read/write; narrowly scoped benchmark/worker reads as needed. Never a CloudFront origin. Versioning on |
| `job-state` | Requests, exact private audits, browser-safe result JSON, text-vector cache | API/worker IAM only; result-specific presigned GET after session authorization. Versioning off for disposable state; no public policy |

All: Block Public Access (all four), bucket-owner-enforced ownership (ACLs off), SSE-S3 encryption, TLS-only bucket policy, no website endpoint, no Transfer Acceleration, no replication, no requester-pays. Use IAM deployment roles; do not embed access keys. SSE-S3 avoids unnecessary customer KMS key/per-request cost for this scope. CloudFront uses the regional S3 REST origin with **OAC always-sign**, exact distribution ARN in the bucket policy. [S077](SOURCES.md).

No raw analysis, embeddings, source paths or private request logs are copied into the public-serving prefix. The frozen library is an allowlist; mapping URLs must not weaken its existing source-hash and complete-analysis checks. API and worker cannot upload songs or modify the release.

## Object metadata and lifecycle

- MP3/mix: correct `audio/mpeg` / `audio/mp4`, exact Content-Length, immutable hash key, `Cache-Control: public,max-age=31536000,immutable`. Do not gzip audio. Signed-cookie checks still run at CloudFront on cache hits; cache lifetime does not grant anonymous access.
- Hashed application assets and versioned catalog pages: one-year immutable cache; gzip/Brotli delivery for JSON/text. Preserve originals/manifests. Split the 16+ MB public catalog into 25-track pages; do not send it through API Gateway/Lambda.
- `library/current.json` and app entry: `max-age=60`; update only after release verification. API and login responses: `private,no-store` with CDN caching disabled.
- Abort incomplete multipart uploads after one day. Retain active and previous complete releases. No automatic expiration of their referenced audio/model/image objects. Hash-addressed media can be shared across releases.
- Versioned buckets: expire noncurrent versions after 30 days only for replaceable pointers/accidental overwrites, never prune the retained release identities; remove expired delete markers. Active immutable keys should not be overwritten.
- Disposable job requests/results/audits: seven-day S3 expiration; text cache: 30 days. Application access expires earlier (24-hour job retrieval). S3 lifecycle is asynchronous, not an exact deletion deadline. On successful jobs, prune old audit pairs beyond 200; lifecycle is the idle cleanup fallback.
- Keep complete verified local release and model bundles. Versioning and CDN caches are not independent backups. Retain a second owner-controlled copy before deleting originals. Cross-region replication and AWS Backup add little value for this recoverable first demo and are deferred.

[S3 versioning semantics](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html).

Use explicit SHA-256 checksums in upload tooling and verify remote object length/checksum against the local inventory. Multipart ETag is not a SHA-256 or universally an MD5. Exercise GET bytes and range boundaries on generated fixtures first and at least three real MP3s after authorized upload. Verify every selected object's integrity before changing `current.json`; no `sync --delete` over the library.

Prove denied anonymous S3 GET, denied CloudFront request without a valid cookie, successful uncached CloudFront origin fetch, and full catalog when the worker is disabled. Restore an old pointer/version in a test prefix and demonstrate rollback from the retained local manifest.
